# 作業時間ログ CLI（仮称: timelog）— 壁打ちメモ

作成日: 2026-08-12
ステータス: アイデア確定 / PRD 化待ち

## 背景と課題

現在は Excel シートで作業実績を管理しているが、**入力の手間**が大きく、集計が面倒になっている。
記録そのものより「記録を残す動作のコスト」と「集計・見返し」がボトルネック。

- 利用範囲: **完全に自分専用・ローカル完結**（同期・サーバ・チーム共有は対象外）
- 時間の単位: **分単位**（0.5h 等への丸めは行わない）

## 基本コンセプト

**REPL 型の対話ツール**。起動しっぱなしにして、作業の切り替えごとにコマンドを打つ。

- プロジェクトを事前登録し、`use` で切り替える
- タスクはプロジェクト配下に事前登録し、番号または名前で呼び出す
- 計測はリアルタイム（start/stop/resume）を主とし、押し忘れは事後入力・事後修正で補う

プロンプト自体に現在の状態を表示することで、`status` 相当のコマンドを不要にする。

```
[myproj] ▶ 認証API実装 00:23 >
```

## コマンド体系（案）

### プロジェクト / タスク管理

```
project add <名前>              プロジェクト登録
project list                    プロジェクト一覧
use <プロジェクト>               作業対象プロジェクトの切り替え
task add <名前>                 現在のプロジェクト配下にタスク登録
task list                       タスク一覧（アーカイブ済みは非表示）
task archive <番号|名前>         タスクをアーカイブ
```

### 計測

```
start <番号|名前> [備考]         計測開始
stop                            計測終了
resume                          直前のエントリを同じタスクで再開
note <テキスト>                  計測中のエントリに備考を付ける
```

### 実績の確認・補正

```
show [日付]                     1日の作業実績を表示（既定は今日）
add <開始> <終了> <番号|名前>     事後入力（タイマー押し忘れ時）
edit <行番号> ...                事後修正（時刻・タスク・備考）
export <YYYY-MM>                CSV 出力
```

## 出力構成

| 日付 | 開始時刻 | 終了時刻 | 作業時間 | プロジェクト | タスク | 備考 |
| ---- | -------- | -------- | -------- | ------------ | ------ | ---- |

備考は追加した場合のみ保持する。

## データ保存

```
~/.timelog/
  projects.json          プロジェクト / タスクのマスタ（アーカイブ状態を含む）
  current.json           計測中の状態（start 時に即書き込み）
  entries/
    2026-08.jsonl        月別・1行1エントリ
```

- エントリは 1 行 1 レコードの JSONL。開始 / 終了は ISO 8601 時刻、作業時間は分単位で保持
- `current.json` を計測開始時点で書き出すことで、REPL が異常終了しても計測状態を復帰できる

## 決定事項（壁打ちで確定）

| 論点               | 決定                                | 理由                                                                                   |
| ------------------ | ----------------------------------- | -------------------------------------------------------------------------------------- |
| インターフェース   | REPL 型                             | 作業の切り替えごとに打鍵するため、起動コストを毎回払わない形にする                     |
| 中断の扱い（lap）  | **lap は導入しない**                | 中断すると出力が自然に 2 行に割れるため、lap は stop→resume と同義になり新概念にならない |
| 日跨ぎ             | **日付境界で行を分割**              | 日付単位の集計と 1 行 1 日の出力構成を保つため                                          |
| タスクの寿命       | **アーカイブを導入**                | 完了タスクが一覧に溜まると番号選択の摩擦が増すため                                      |
| タスクの呼び出し   | **番号 + 名前補完の両対応**         | 数字なら番号、文字列なら部分一致として解釈。並びは最近使った順                          |
| 備考の入力         | **計測中（note）＋事後修正（edit）** | 作業前には書けないことが多く、後から思い出すことも多いため                              |
| 時間の単位         | 分単位（丸めなし）                  | 個人用のため、工数表向けの丸め配分は不要                                                |
| CSV の備考列       | **列は固定、値が空欄**              | 表計算に貼る前提のため、行ごとに列数が変わらない方が扱いやすい                          |
| note の複数回実行  | **上書き**                          | 追記だと意図しない冗長化が起きる。積み上げたい場合は edit で書き直す                    |
| REPL 終了時の計測中 | **警告して終了を中止**              | 計測しっぱなしのまま終了すると記録が壊れるため、stop を促す                             |
| 起動時の計測中状態 | **終了時刻を尋ねて確定させる**      | 異常終了時の復帰導線。放置された計測を実態に合わせて閉じられる                          |
| export の文字コード | **UTF-8 / BOM 付き UTF-8 を選択可** | Excel で開く用途と、他ツールに渡す用途の両方があるため                                  |
| show の集計粒度    | **タスク別小計を表示**              | 「集計が面倒」という元の課題に直接効く部分のため                                        |
| アーカイブの対象   | **プロジェクト・タスクの両方**      | プロジェクトも増え続けるため、一覧の摩擦は同じ問題が起きる                              |
| 日跨ぎ分割の実行   | **stop 時に実行**                   | 計測確定のタイミングでまとめて処理する                                                  |

## 実装上の補足

### 日跨ぎ分割は回数を固定しない

分割は「日付境界ごとにループで割る」実装にする。1 回だけ割る特別扱いにしても
コードが単純になるわけではなく、むしろ境界の数え方が例外的になる。

複数回の分割が実際に起きうるのは、stop を押し忘れて金曜夜から月曜朝まで
REPL を放置したようなケース。起動時の復帰導線（終了時刻を尋ねる）を用意する以上、
このパターンは想定内として扱う。

### 終了フローと復帰フローの関係

- 通常終了時に計測中なら **exit を中止**して stop を促す
- そのため起動時の復帰処理（終了時刻を尋ねる）が動くのは、
  クラッシュや強制終了で `current.json` が残ったケースに限られる
